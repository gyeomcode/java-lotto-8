## 프로젝트 요약

사용자로부터 로또 구입 금액, 당첨 번호 및 보너스 번호를 입력받아 당첨 내역, 수익률을 출력한다.

## 요구 환경

- Java 21

## 입출력 예시

```
구입금액을 입력해 주세요.
5000

5개를 구매했습니다.
[11, 21, 27, 30, 31, 43]
[14, 15, 17, 24, 27, 45]
[2, 21, 25, 29, 36, 38]
[4, 6, 9, 19, 39, 41]
[12, 19, 24, 28, 34, 39]

당첨 번호를 입력해 주세요.
11,21,27,30,31,40

보너스 번호를 입력해 주세요.
43

당첨 통계
---
3개 일치 (5,000원) - 0개
4개 일치 (50,000원) - 0개
5개 일치 (1,500,000원) - 0개
5개 일치, 보너스 볼 일치 (30,000,000원) - 1개
6개 일치 (2,000,000,000원) - 0개
총 수익률은 600,000.0%입니다.
```

## 예외 처리 예시

사용자가 잘못된 값을 입력할 경우 IllegalArgumentException을 발생시키고, "[ERROR]"로 시작하는 에러 메시지를 출력 후 그 부분부터 입력을 다시 받는다.

```
구입금액을 입력해 주세요.
5000

5개를 구매했습니다.
[1, 5, 9, 11, 22, 34]
[6, 18, 23, 25, 31, 32]
[1, 3, 6, 8, 22, 40]
[4, 6, 9, 14, 26, 40]
[8, 12, 17, 18, 24, 44]

당첨 번호를 입력해 주세요.
1,2,3,4,5
[ERROR] 당첨 번호의 개수는 중복 없이 6개여야 합니다.

당첨 번호를 입력해 주세요.
```

## 학습 목표

- 관련 함수를 묶어 클래스를 만들고, 객체들이 협력하여 하나의 큰 기능을 수행하도록 한다.
- 클래스와 함수에 대한 단위 테스트를 통해 의도한 대로 정확하게 작동하는 영역을 확보한다.
- 2주 차 공통 피드백(디스코드 참고)을 최대한 반영한다.

## 프로그래밍 요구 사항

- [X] 값을 하드 코딩하지 않는다.
- [X] 클래스는 상수, 멤버 변수, 생성자, 메서드 순으로 작성한다.
- [X] 변수 이름에 자료형은 사용하지 않는다.
- [X] indent(인덴트, 들여쓰기) depth는 2까지만 허용한다.
- [X] 3항 연산자를 사용하지 않는다.
- [X] 함수의 길이가 15라인을 넘어가지 않도록 한다.
- [X] 함수가 한 가지 기능만 담당하게 한다.
- [X] `else`, `switch/case`를 사용하지 않는다.
- [X] Java Enum을 적용한다.
- [X] Random값 추출은 `camp.nextstep.edu.missionutils.Randoms`의 `pickUniqueNumbersInRange()`를 활용한다.
- [X] 사용자 입력은 `camp.nextstep.edu.missionutils.Console`의 `readLine()`를 활용한다.
- [X] 제공된 `Lotto` 클래스를 사용하여 구현한다.
- [X] 단위 테스트를 작성한다.

## 기능 목록

### 입력

- [X] 로또 구입 금액을 입력받는다.
    - [X] 문자열을 trim 처리한다.
    - [X] 문자열을 숫자로 변환한다.

- [X] 로또 구입 금액 입력을 예외 처리한다.
    - [X] 숫자가 아닌 경우
    - [X] 1,000원으로 나누어 떨어지지 않는 경우
    - [X] 0 이하인 경우
    - [X] Integer.MAX_VALUE를 초과한 경우

- [X] 당첨 번호를 입력받는다.
    - [X] 당첨 번호는 쉼표를 기준으로 분리한다.
    - [X] 각 번호를 trim 처리한다.
    - [X] 각 번호를 숫자로 변환한다.

- [X] 당첨 번호 입력을 예외 처리한다.
    - [X] 개수가 6이 아닌 경우
    - [X] 중복되는 숫자가 있는 경우
    - [X] 숫자가 아닌 경우
    - [X] 0 이하인 경우
    - [X] 45를 초과한 경우

- [X] 보너스 번호를 입력받는다.
    - [X] 문자열을 trim 처리한다.
    - [X] 숫자로 변환한다.

- [X] 보너스 번호 입력을 예외 처리한다.
    - [X] 당첨 번호와 중복되는 숫자가 있는 경우
    - [X] 숫자가 아닌 경우
    - [X] 0 이하인 경우
    - [X] 45를 초과한 경우

- [X] 발생한 예외를 처리한다.
    - [X] `[ERROR]`로 시작하는 에러 메시지를 출력한다.
    - [X] 해당 부분부터 입력을 다시 입력받는다.

### 로또

- [X] 로또 번호를 발행한다.
    - [X] 로또 구입 금액만큼 반복한다.
    - [X] 로또 번호를 오름차순 정렬한다.

- [X] 로또 번호를 예외 처리한다.
    - [X] 개수가 6이 아닌 경우
    - [X] 중복이 있는 경우
    - [X] 1에서 45 사이의 값이 아닌 경우

- [X] 당첨 내역을 계산한다.

- [X] 수익률을 계산한다.
    - [X] 소수점 둘째 자리에서 반올림한다.

### 출력

- [X] 발행한 로또 수량 및 번호를 출력한다.

- [X] 당첨 내역을 출력한다.

- [X] 수익률을 출력한다.

## 가장 오래 고민했던 부분

구현 과정에서 가장 많은 시간을 투자한 부분은 당첨 내역 계산 시 시간 복잡도를 최소화하는 방안을 도출하는 일이었다.

현실 세계에서 로또를 구매해 당첨 내역을 수동으로 확인한다고 가정했을 때 로또 구입자는 로또 용지를 들고 당첨 번호와 보너스 번호를 비교해 일치 여부를 확인한다.

이를 프로그램에서 처리할 경우 입력으로 주어지는 금액을 int 타입으로 관리하면 1,000원 단위로 나누어 떨어지는 최대 금액은 2,147,483,000원이며, 최대 2,147,483장의 로또를 생성할 수 있다. (
다만 실제 환경에서는 로또 구입 금액이 10만 원으로 제한된다.)

로또 한 장에는 6개의 번호가 있고 당첨 번호 또한 6개이므로, 최대 구매 가능 수량을 기준으로 한 최악의 경우 시간 복잡도는 다음과 같다.

```
2,147,483 * 6 * 6 = 77,309,388
```

이는 실행 속도에 치명적인 수준은 아니지만, 이진 탐색을 적용하거나 당첨 번호를 HashSet으로 변환해 비교 연산을 효율화할 수 있다고 판단했다. 당첨 번호는 중복이 없고 HashSet의 contains 연산은
평균 시간 복잡도가 O(1)이므로 성능 개선에 유리하다. 저장되는 원소가 6개로 제한되고 값의 범위도 1부터 45까지로 명확히 한정되어 있어 해시 충돌 가능성은 사실상 무시할 수 있다.

- HashSet은 요소 수보다 큰 버킷 배열을 사용한다.
- 1에서 45의 값은 모두 다른 해시 코드를 가진다.
- HashSet으로 변환하는 작업은 로또 한 장마다 한 번만 수행하면 되며, 처음부터 당첨 번호를 HashSet으로 관리하는 방식도 가능하다.

따라서, 개선된 시간 복잡도는 다음과 같다.

```
2,147,483 * 6 = 12,884,898
```

## 테스트를 작성하는 이유

과제를 통해 단위 테스트를 작성하며 체감한 가장 큰 장점은 테스트 수행 시간이 단축되었다는 점이다. 초기에는 테스트 도구 사용에 익숙하지 않아 테스트 작성에 많은 시간이 소요되었다. 그러나 점차 도구에 익숙해지면서
기능 구현 후 IDE로 프로그램을 실행하고 데이터를 직접 입력하는 절차를 생략할 수 있게 되었고, 필요 부분만을 바로 검증할 수 있어 테스트 수행 시간이 크게 감소했다.

또한 규모가 큰 리팩터링을 수행할 때도 테스트 코드를 통해 변경된 프로그램의 정상 동작 여부를 즉시 확인할 수 있었고, 이로 인해 리팩터링 후 디버깅에 소요되는 시간이 크게 줄었다.

즉, 테스트 코드 작성은 테스트 수행 시간과 디버깅에 소요되는 시간을 효율적으로 단축한다.
